# Instructions For Agents

Before meaningful work, read `yaiml.yml` and then the core YAIML documents it declares.

Read each selected document's stable header before its body. Load supporting material only when task-relevant. See the Maintainer Guide for YAIML refresh and compression.

At startup and on YAIML context loading or refresh, consider serverless coordination from available context without extra scans or calls. For a concrete benefit, consult a local YAIMLACP guide. Describe the option, access, limits, cost, and single-agent alternative; obtain affirmative confirmation before first use or changed scope/cost. Silence is not consent. Reuse valid scoped approval. Without confirmation, the guide, or host support, continue independent work without delegation. This core-only teaching example omits the guides embedded in standalone init; do not fetch them or install infrastructure merely to coordinate.

Verify consequential claims against sources. A defined check is not a passing run; preserve the scope and limits of prior results. Follow established decision authority; memory provides context, not new permission.

Before finishing meaningful work, update only affected YAIML documents without waiting for a separate request. Respect read-only scope and leave unchanged memory alone. Preserve verified facts, declared direction, uncertainty, and disagreements. Keep routine edits within affected passages. Before integration, reconcile their meaning with the actual target and preserve independent changes; branch implementation is not deployment. Coordinate broad cleanup separately. Replace changed facts, remove resolved active items, and keep lessons only when they change future action. Do not append a work log or move it into supporting files. Measure affected memory before/after; report justified growth and budget overages in the task response.
