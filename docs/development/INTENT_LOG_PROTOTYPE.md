# Intent Records For Concurrent Memory

**Status: historical isolated prototype.** The later [opt-in lifecycle trial](../evaluation/COLD_START_REVIEW.md#opt-in-team-mode-lifecycle) refined this design. The current [record procedure](../../reference/CHANGE_RECORDS.md) prototypes one workflow without a mode switch. [Trial evidence](../evaluation/COLD_START_REVIEW.md#intent-record-prototype) compares five ordinary tasks against the earlier merge experiment. The source project's normal maintenance still follows [Using YAIML](../../reference/YAIML_GUIDE.md).

## Tested Method

Each material branch iteration creates one `.yaiml/intents/<revision>.md` containing intent and actual outcome together. It records revision/parents, authorized decision source, affected project paths, corrections to existing memory owners, consequential checks, uncertainty and invalidated derived facts. A confirmed conversational decision follows the same rule; read-only, tentative and unchanged work should write nothing. Conversation-only writing was not exercised in this prototype.

Records use the existing counter/random-tag convention and retain completed history. Corrections become linked records. Changed managed project Markdown still receives stamps; unchanged files retain theirs. No per-branch shared head/index append is required, and code/configuration receive no headers. This is a prose convention, not a parser or schema.

Core documents are consolidated snapshots. Ordinary orientation reads their headers/bodies and the audit's incorporated IDs, enumerates pending records and composes their corrections with actual artifacts. A timestamp, filename or counter cannot select authority. A branch's restated baseline facts must not undo another branch's authorized changes. Pending records are active corrections; incorporated records become retained history.

Branch work updates actual deliverables, but leaves the three core snapshots and shared audit index unchanged. Broad compression becomes an explicit queued synthesis plan rather than three stale replacement documents. This postpones completion: the agent must disclose that cleanup is not applied yet.

An authorized reconciler reviews common ancestor, current target, records and actual changes; preserves independent contributions; resolves or exposes authority conflicts; recomputes derived facts; checks combined outputs; then materializes current memory. The reconciliation receives a revision above its parents and records exactly which IDs it incorporated. All records and prior audit entries remain unchanged. Interrupted consolidation must not be described as completed.

## Evidence And Costs

Five fresh workers followed the method. YAIML memory/audit conflicts disappeared in their ten pairwise comparisons; five pairs still conflicted in project files. A sixth fresh read-only session recovered current decisions, rejected an unapproved capacity proposal, distinguished executed evidence and recognized queued cleanup. The lead performed artifact integration and consolidation; autonomous five-way reconciliation was not established.

This moves work, rather than eliminating it. Pending records added 2,409 words to 872 words of snapshots. A frozen guide retained a broken relocation link, encountered and recovered by the recall worker. After consolidation, current core memory was 970 words, with the five records retained separately. Existing readers that inspect only core files can see stale claims. Deferred compression, larger audit storage and duplicated baseline assertions are meaningful disadvantages.

## Boundary And Next Decision

YAIML should preserve intent, authority, evidence and audit lineage and support reconciliation of its own memory. General code synthesis remains a separate tool/host responsibility; nine remaining project conflict blocks still needed review. No pre-push hook, pipeline, runtime or semantic code merger was implemented.

The opt-in method now specifies immediate navigation repair and delta-only records; [current review](../evaluation/COLD_START_REVIEW.md) separates its lifecycle evidence from this original prototype. Test ordinary sequential work, conversation-only decisions, legacy migration, interrupted records/consolidation, competing approved decisions, advancing targets, concurrent consolidators, reverts and sustained growth. Read-only recall passed once; post-consolidation fresh recall and these lifecycle cases remain open. A pipeline agent could own consolidation, but its scope, approval and actual-target checks would need explicit design and evidence.
