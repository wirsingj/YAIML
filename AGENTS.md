## Source-Project Boundaries

- YAIML means **Yet Another AI Markup Language**: shared project memory for humans and agents. Preserve human direction in SoTY and the distinction between intent and implementation evidence.
- This repository develops the reusable product while using it. Canonical product methods live in `reference/skills/`; `.agents/skills/yaiml-*` are native routes. Every init form distributes only agnostic guidance, methods and templates, with notices/provenance. Our populated memory, discovery, instructions, decisions, checks, history and release plans stay source-only, even through indirect references. Bootstrap identifies reusable resources; our [hello-world](.yaiml/skills/hello-world/SKILL.md) route stays local, outside the distributed catalog.
- Here, “update YAIML” means improve reference guidance within scope and maintain affected project memory, not run consumer acquisition over authored sources. Source-project init likewise maintains canonical resources/routes in place; this exception belongs here, not in consumer prompts. “Update our SoT” selects ordinary maintenance; cleanup/compression requests select synthesis. Preserve legacy discovery inputs and mature adopter knowledge.
- New source-project-local skills stay in `.yaiml/skills/` and local instruction routes, not the distributed catalog. Only explicitly approved reusable methods enter `reference/skills/`.
- Keep repository navigation product-first: `reference/` is reusable material, `docs/` is product explanation/development/evaluation, `examples/` is teaching material, and root `ROADMAP.md` is public direction. `.yaiml/` is only this project's own context, audit and local methods. Link existing project artifacts from discovery; do not move them into memory because they are Markdown or discuss YAIML.
- Synchronize affected guides, templates, prompts and routes with their owning method. Keep examples explicitly scoped; source-project dogfooding and fresh adopter behavior require separate evidence.
- Follow the [evidence guidance](docs/AMBIGUITY_AND_EVIDENCE.md#contradictions-and-regression-checks) for disputed behavior and acceptance authority. Keep disputed candidates out of shared defaults while investigating.
- Keep this phase convention-first: no runtime, server, SDK, provider adapter, package manifest or web app without authorized implementation scope. Do not revive `SPEC.md`, Markdown schemas or formal conformance machinery. YAIMLACP uses existing host capabilities only.
- Preserve `LICENSE.md`, attribution and earlier grants. Commercial/client use is allowed; selling YAIML or charging for forks is restricted. Further terms changes require explicit maintainer approval. Do not call the custom terms MIT or OSI-approved open source.
- Preserve the independence declaration and exclude confidential/private material. Machine-specific reference paths, drive/profile names, file URIs, localhost and private workspace URLs belong in prompts, workspace configuration or ignored notes, never committed guidance.

Before finishing, apply the shared guide's maintenance and revision steps without a separate request. Keep current memory concise and retain the audit under its policy. Report affected memory counts, growth reasons and budget overages outside memory. Respect read-only scope and leave unchanged understanding alone.
